05What changed since the July plan

  • Pleo MCP server (docs published 2026-08-17, https://mcp.pleo.io/mcp): browser OAuth, no credentials to store. An admin enables it per entity under Settings, General, Pleo AI. It can search expenses, identify expenses missing details or receipts, attach receipts, set categories, tags, notes and tax codes, and add expenses to the export queue. It cannot make payouts, and there is no documented tool to create an out-of-pocket expense. One OAuth connection covers both entities once each entity's admin has opted in. Two caveats: Pleo publishes no tool list (it is labelled beta), and receipt attachment is described as link-based, "directly from the link, no downloading or uploading required", with no documented local-file upload. So the agent must hand Pleo a fetchable link, or download the PDF and serve it from somewhere Pleo can reach. "Included with eligible plans" is all the pricing docs say.
  • Accounting Entries API went GA on 2026-06-24 and an Enrichment API attaches receipts to card expenses by amount, currency, card last four and merchant. Still gated behind the keys Pleo declined to issue, so a re-request is worth one email but not worth waiting for.
  • Fetch was never actually connected during the June and July runs. The handovers' "connected" claim conflated "forwarding to forward@fetch.pleo.io works" (which needs no OAuth) with "Fetch is scanning the inbox".
  • The Claude Gmail connector can forward, which the June dead-ends list said was impossible. If attachments survive, the agent can do the forwarding step you have been doing by hand.
  • CCA now suppresses Pleo mail, so the reminder signal needs its own route into a finance workflow rather than the client-awareness feed.
