## Layout

- `data/amex/` Amex portal exports `activity*.csv` (gitignored). Drop new ones here.
- `data/pleo/` Pleo downloads, unzipped, one folder per download (gitignored).
- `out/` generated ledgers and worklists (gitignored).
- `scripts/amex_import.py` normalises Amex exports into one de-duplicated ledger. Tested on the three May to August 2026 files: 149 rows, 137 charges, 263 984,07 SEK.
- `scripts/pleo_export_profile.py` profiles a Pleo download and lists rows without receipts. Tested on the 2026-08-21 export: 181 rows, 30 without receipts.
- `scripts/gmail_fetch.py` read-only receipt fetcher on top of Thor's Gmail DWD script (`links`, `save`, `html` subcommands, `--reason` required, audited). On 2026-08-21 it saved the 9 Gmail-located Pleo receipts (Vercel, Google One x2, Firecrawl x2, Supabase, Anthropic Max, Apple, Brave) into `out/receipts/`; HTML-only receipts were rendered to PDF. `out/receipts/MATCHING.csv` maps each Pleo receipt number and expense id to the file to attach.
- `scripts/classify.py` classifies a raw `amex_import.py` ledger into business/personal/needs-tag/skip and attaches kontering (built 2026-08-24). Encodes the card rules (-61022 business default post-split, -62004 personal, -13003 excluded with the bounded KINTO exception, -61006 personal from 2026-06-04, split date 2026-06-15), reads `scripts/merchant_rules.json` (vendor tag + entity + BAS-konto + vat_regime), seeds from a `--prior` classified ledger (needs-tag rows stay queued for Oscar, never inferred), and takes Oscar's answers via `--overrides` CSV (ref,tag,note). Output is gmail_match-compatible (`amex_classified`). Regression 2026-08-24: reproduces the canonical 149-row ledger exactly (business 32, personal 88, needs-tag 17, skip 12; 145 737,28 SEK business).
- `scripts/fortnox_lane.py` month-end Fortnox plan builder (built 2026-08-24, stdlib only, makes NO API calls). Takes a classified ledger and a month, selects business/viseo rows, and writes `out/fortnox-run-<YYYY-MM>/`: one balanced voucher payload per row (domestic 25/12/6, KINTO half-VAT, EU and non-EU reverse charge via 2614/2645, OSS rows booked gross and flagged), `salary/utlagg.json` (one Fortnox Lon utlagg row for the month's total against 2890), `manifest.csv`, a Swedish `plan.md` for Oscar, and `commands.sh` (fortnox CLI dry-run lines plus commented APPROVED execute lines with exact confirm phrases). Excluded rows (needs-tag, 5555 Media, missing konto) are always listed, never silently dropped. Payloads validated against the fortnox CLI's own dry-run. The fortnox CLI in Thor was extended the same day with `write voucher / inbox-upload / voucher-file-connection / salary-transaction` plus vouchers/inbox/salary-transactions/employees reads, all dry-run gated; they need the pending scope re-consent to execute.
- `scripts/merchant_rules.json` vendor rules for classify.py: tag default, entity (viseo/5555media), BAS-konto, vat_regime, per the kontering proposal in `out/kontering-forslag-2026-08-24.txt` (pending Nicolina's one-time review).
- `scripts/amex_receipts.py` automated Gmail receipt fetch for classified Amex business rows (built 2026-08-24): known evidence ids win, otherwise gmail_match's own scoring decides and only strong matches are fetched; junk attachments filtered; per-month map CSV consumable by fortnox_lane `--receipts-map`; `--dry-run` replays the cache with zero network calls. First live runs fetched Inet, Wincher x2, Ahrefs and DataForSEO across May, June and July.
- `scripts/fortnox_execute.py` executes an approved plan via the fortnox CLI (built 2026-08-24). Approval model: the dry-run prints the batch and an APPROVAL CODE (sha256 over the exact payload bytes); execution requires `--execute --approve <code>` from Oscar, so the CLAUDE.md per-batch approval gate is enforced by construction. Chain per row: inbox upload (folderid inbox_v) -> voucher -> voucher-file-connection, then one salary utlagg; progress checkpointed in execution.json, idempotent resume, double-salary guard.
- `scripts/month_end.py` the whole month in one command: classify -> amex_receipts -> fortnox_lane, then prints the fortnox_execute step. Nothing executes without Oscar's code.
- `scripts/tests/` + `scripts/run_checks.sh` offline test suite (183 checks: voucher math per VAT regime, classify rule order, plan artifacts) plus compile checks and the classify regression against the canonical ledger. All synthetic fixtures, no live calls.
- `scripts/gmail_match.py` read-only Gmail receipt matcher (built 2026-08-21, 1 688 lines, stdlib plus the DWD module). Auto-detects every ledger format in `out/`, resolves the vendor via `scripts/vendor_aliases.json` (32 vendors, editable), searches a date window around the charge, scores amount (SEK or foreign) + date + sender + subject + attachment, never card digits, and routes each row: `confirm` (already forwarded to Fetch), `forward` (Pleo row under 40 days), `attach` (Pleo row 40 days or older), `pack` (tagged-business Amex row), `portal`, `none`. Caches lists and message extracts in `out/gmail-cache.json` (no body text stored). `--check out/receipts/MATCHING.csv` is the regression: 9 known receipts must rank first. `--short-csv` writes the person-facing list. Every API call carries `--reason` into Thor's audit log, retries included.
- `docs/` the three review pages as published on 2026-08-21: `kvittolaget.html` (setup review and decisions), `amex-kon.html` (Amex worklist), `pleo-kon.html` (Pleo missing-receipt worklist).
- `reference/` prior art: the June dashboard CLIs and API code, the July closeout pack README and manifest, the July lane proposal, and the research journals with Gmail message ids (`reference/evidence/`, gitignored).
